# /backtest-analyze — 백테스트 결과 분석

백테스트 결과를 올바르게 해석하고 실거래 투입 가능 여부를 판단합니다.

## 사용법

```
/backtest-analyze                    # 현재 디렉토리의 백테스트 결과 분석
/backtest-analyze results.json       # 특정 결과 파일 분석
/backtest-analyze --regime           # 시장 레짐별 성과 분리 분석
```

## 핵심 지표 계산 및 해석

### 수익성
| 지표 | 계산 방법 | 합격 기준 |
|------|----------|----------|
| 샤프 비율 | (연간 수익률 - 무위험 수익률) / 연간 변동성 | ≥ 1.0 |
| 소르티노 비율 | 샤프와 같으나 하방 변동성만 사용 | ≥ 1.5 |
| 수익 팩터 | 총 수익 / 총 손실 | ≥ 1.5 |
| 기대값 | (승률 × 평균 수익) - (패율 × 평균 손실) | > 0 (수수료 포함) |

### 리스크
| 지표 | 합격 기준 |
|------|----------|
| 최대 드로다운 | ≤ 20% |
| 드로다운 회복 기간 | ≤ 30일 |
| Calmar Ratio (연간수익/MDD) | ≥ 1.0 |
| 연속 최대 손실 횟수 | ≤ 10회 |

### 통계적 유의성
- 거래 횟수 ≥ 30회 (최소), ≥ 100회 권장
- 테스트 기간 ≥ 1년 (여러 시장 레짐 포함)
- OOS(Out-of-Sample) 성과 확인 필수

## 레짐별 분리 분석

백테스트 기간을 자동으로 4개 레짐으로 분리:
```
📈 상승장  : 성과 vs 기대치
📉 하락장  : 성과 vs 기대치
↔️ 횡보장  : 성과 vs 기대치
⚡ 급등락  : 성과 vs 기대치
```

→ 특정 레짐에서만 잘 작동하면 실거래에서 실패 위험 높음

## 룩어헤드 바이어스 체크

```python
# 위험 패턴 자동 탐지
- 현재 캔들 종가로 현재 캔들 신호 생성 (미래 데이터)
- resample() 후 즉시 shift(0) 없이 사용
- rolling().mean()의 min_periods 설정 누락
```

## 수수료 현실화

```
백테스트 수익률 - 실제 비용 = 실제 기대 수익률

실제 비용 계산:
  수수료    : 왕복 0.1~0.2% (거래소별 상이)
  슬리피지  : 0.02~0.1% (유동성에 따라)
  펀딩피    : 선물 시 8시간마다 ±0.01%
```
