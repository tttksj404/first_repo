# /strategy-drift — 전략 성과 이탈 감지

실거래 성과가 백테스트에서 유의미하게 벗어났는지 통계적으로 판단합니다.
시장 레짐 변화 또는 전략 고장을 조기에 감지합니다.

## 사용법

```
/strategy-drift                      # 전체 전략 드리프트 분석
/strategy-drift --window 14          # 최근 14일 기준
/strategy-drift --alert-only         # 경고 항목만 출력
```

## 드리프트 감지 지표

### 핵심 지표 비교

| 지표 | 백테스트 기준값 | 경고 임계치 | 중단 임계치 |
|------|---------------|------------|------------|
| 승률 | 기준값 | -10%p | -15%p |
| 수익 팩터 | 기준값 | -20% | -35% |
| 평균 수익(R) | 기준값 | -25% | -40% |
| 샤프(월간) | 기준값 | -30% | -50% |
| 거래 빈도 | 기준값 | ±40% | ±60% |

### 통계적 유의성 판단

단순 수치 비교가 아닌 통계 검정 적용:
```python
# Chi-square test: 승률 이탈 여부
from scipy import stats
observed = [wins, losses]           # 실거래
expected = [backtest_wr * n, (1-backtest_wr) * n]
chi2, p_value = stats.chisquare(observed, expected)

if p_value < 0.05:
    # 95% 신뢰수준에서 유의미한 이탈
    print("⚠️ 통계적으로 유의미한 성과 이탈")
```

## 원인 진단

드리프트 감지 시 자동으로 원인을 분류:

### A. 시장 레짐 변화 (가장 흔함)
```
증거: 모든 전략이 동시에 성과 저하
      VIX/시장 변동성 급변
      상관관계 있는 다른 지표들도 이탈
대응: 전략 일시 중단 + 레짐 안정화 대기
```

### B. 전략 고장 (코드 문제)
```
증거: 특정 날짜 이후 갑작스러운 성과 전환
      특정 오더 타입에서만 이탈
      로그에서 예외 처리된 주문 급증
대응: 코드 변경 이력 확인 + /trade-debug 실행
```

### C. 데이터 품질 문제
```
증거: 특정 시간대에만 성과 이탈
      API 에러 로그와 겹치는 시점
대응: /exchange-debug 실행
```

### D. 과최적화 (정상적 성과 저하)
```
증거: 서서히 저하, 급격한 전환점 없음
      레짐 변화와 무관
대응: /backtest-analyze --regime 재실행 + 파라미터 재최적화
```

## 자동 대응 권고

```
NORMAL      → 현 전략 유지
⚠️ WARNING  → 포지션 크기 75% 감소 + 일일 모니터링
🔴 CRITICAL → 신규 진입 중단 + 기존 포지션 관리만
💀 HALT     → 봇 완전 정지 + 전략 재검토
```
